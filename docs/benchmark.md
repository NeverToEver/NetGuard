# NetGuard 性能与检测能力基准

本页数据由 `python scripts/benchmark.py` 生成，用于量化抓包解析、流水线吞吐、
规则匹配延迟与检测能力，结果可直接引用到 README 或简历。

## 复现方式

```bash
# 默认规模（10 万包）
python scripts/benchmark.py

# 指定规模并输出 JSON
python scripts/benchmark.py --packets 200000 --rules 500 --json docs/benchmark-results.json

# 追加输出 Markdown 表格
python scripts/benchmark.py --markdown
```

## 测试环境

| 项 | 值 |
|---|---|
| 平台 | Windows 10 (win32) |
| Python | 3.11.9 |
| CPU | 本机单核（未做绑定） |
| 流量 | `netguard.trafficgen` 的 12 种正常模板合成，无真实网卡 |

> 说明：合成为纯内存流量，不含真实内核抓包与网卡中断开销，因此解析/流水线数字
> 代表**用户态处理上限**，真机抓包吞吐会受 libpcap/Npcap 与内核影响。

## 主要结果（20 万包，500 条规则）

| 项目 | 结果 |
|---|---|
| 协议解析吞吐 | 约 12.7 万 包/秒（约 8.3 MB/s） |
| 单包解析耗时 | 约 7.9 µs |
| 端到端流水线（解析+会话+规则+检测） | 约 5.1 万 包/秒（约 3.3 MB/s） |
| 规则匹配延迟（500 条同协议规则） | 中位约 247 µs，P99 约 589 µs |
| 内存增量（处理 5 万包） | 约 8.9 MB |
| 合成攻击场景检出 | 3 / 3 |
| 正常流量误报率 | 0.100%（1 / 1000 包） |

原始数据见 [`benchmark-results.json`](benchmark-results.json)。

## 检测能力

| 场景 | 构造 | 阈值 | 结果 |
|---|---|---|---|
| SYN Flood | 5s 内 150 个 SYN 发往同一 (IP, 端口) | 100 | 命中 |
| 端口扫描 | 10s 内同一源访问 40 个不同目的端口 | 20 | 命中 |
| DNS 隧道 | 10s 内 60 次超长子域查询 | 20 | 命中 |
| 正常流量 | 12 种正常模板各 1000 包 | — | 1 次误报 |

## 已知限制

- **规则匹配为按协议的全量扫描**：引擎只按协议（TCP/UDP/HTTP/DNS/ANY）分桶，
  同一协议下的规则需逐条匹配。因此 500 条 TCP 规则时延迟明显上升。后续可按
  目的端口建立二级索引来降低候选数。
- **检测器阈值需按环境调参**：默认阈值面向实验/演示，生产环境应结合基线调整。
- **合成流量不代表真实分布**：真实网络的包长、协议混合与突发性更复杂。
- **未测真实抓包丢包率**：需要 Npcap/libpcap 与管理员权限，本环境未做端到端实测。
